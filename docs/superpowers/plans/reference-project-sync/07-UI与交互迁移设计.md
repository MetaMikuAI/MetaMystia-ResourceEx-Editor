# UI 与交互迁移设计

## 1. 迁移基准

本项目现有首层 UI/交互为草案，不作为视觉兼容基准。迁移验收分为两类：

### 必须保持

- 根 `/` 重定向与 12 个编辑 URL、各编辑器业务能力和现有游戏术语；
- ResourceEx 字段语义、兼容归一化、校验和导出结果；
- 新增、编辑、删除、排序、跨实体引用和资产管理结果；
- 未保存状态、导入/清空保护和导出后的状态复位；
- 键盘可操作、焦点可见、关闭后焦点回收和 reduced-motion。

### 允许替换

- 页面分栏、卡片、间距、断点、颜色层级和空状态；
- 当前 design wrapper 的公开 props；
- 自制 Select、TextInput、TextArea、移动菜单和固定操作条；
- 原生 `alert`/`confirm`；
- 草案式 hover、pressed、Modal 滚动和 Tooltip 行为。

目标不是逐像素复刻参考项目，也不是只模仿 className。通过必要性门的 Design 叶子应保留固定参考提交中的 motion、reduced-motion、blur、portal、滚动和焦点机制，再接入本项目业务动作；没有目标调用者的参考组件不迁入。

## 2. 页面层级

### App Shell

- 桌面端使用 HeroUI Navbar 原语组合路由组、当前路由状态、主题入口和文件动作。
- 移动端使用 `NavbarMenuToggle`/`NavbarMenu`，按资源包、内容、任务事件、资产分组显示卡片式入口。
- 菜单项先关闭菜单再导航；上传、创建、导出、公告和 GitHub 仍保留。
- 不迁入参考项目的账户、搜索、震动、全局 overlay 协调、进度条、站点状态和 FontAwesome。

### Editor Shell

参考 catalog/admin 的 Header、Panel、Card 和 Placeholder 组合模式，建立编辑器专属布局：

```text
EditorScreen
├─ EditorHeader：标题、说明、全局动作和状态
└─ EditorWorkspace
   ├─ EntityListPanel：搜索/新增/排序/实体列表
   └─ EditorPanel：选中实体表单或 Placeholder
```

- 桌面端维持列表和编辑区并列；超宽屏只增加内容上限与留白，不无限拉宽字段。
- 窄屏按 feature 的实际信息密度改为上下布局或可折叠列表。
- `selectedIndex`、`previewFoodId`、`activeFolder`、`isCollapsed` 等只在 feature Screen/子组件内存在。
- ID/Label 编辑中可能暂时重复，因此不在本次迁移中强制把选择键改为 ID。

不迁入 `fontAwesomeIconButton`、QR、站点元数据、TimeAgo、参考 Loading、driver.js、公告轮播和没有本项目调用者的 Design 叶子。

`.surface-pressable` 的 12 个调用点必须按现有 DOM 语义分开处理：

| 现有 owner                                                                    | 数量 | 现状与目标                                      |
| ----------------------------------------------------------------------------- | ---- | ----------------------------------------------- |
| asset route、CharacterList、MissionList、EventList                            | 4    | 本来就是原生 `<button>`，迁为 Design Button     |
| BeverageList、ClothesList、FoodList、IngredientList、MerchantList、RecipeList | 6    | 含独立删除按钮的 `<div>`，迁为非 pressable Card |
| DialogPackageList                                                             | 2    | 含独立子操作的 `<div>`，迁为非 pressable Card   |

后两类不能给整个 Card 添加 `role="button"`/`tabIndex` 或 PressElement，否则会形成嵌套交互与重复焦点。列表选择必须由 Card 内独立的语义按钮触发，删除等子操作保持自己的按钮和确认 Popover。

## 4. Select 与表单契约

编辑器 Select 的目标 public contract 保留：

- `value` 为 `string | number | undefined`，`onChange` 返回原始值类型；
- 扁平 items 与 sections；
- disabled item、description、`textValue`、placeholder；
- `id`、`ariaLabel`、`size`、`className`、`isInvalid`、`isDisabled`；
- 菜单最大高度与长列表键盘滚动；
- controlled selection、键盘导航、Escape 关闭和焦点回收。

底层改用 HeroUI Select，而不是当前 Dropdown 模拟实现；参考仓库的 `@heroui/select` patch 原样复制并按包名登记。目标保留业务值适配，但不额外恢复该 patch 已移除的打开时自动滚动。

表单规则：

- 文本、数字和 textarea 使用 Design Input/Textarea 视觉与焦点语义；
- Label、帮助文本、错误文本由编辑器字段组件组合；
- `isInvalid` 与错误文案同时输出，不只用颜色表达；
- 游戏字段的空值、`undefined`、`null` 和默认值语义保持现状，不由 UI wrapper 自动归一化。

## 5. 确认、错误与反馈

当前 35 个原生 `alert`/`confirm` 按上下文替换：

| 场景                                    | 目标交互                                              |
| --------------------------------------- | ----------------------------------------------------- |
| 列表项删除、精灵/羁绊删除               | 锚定触发按钮的确认 Popover                            |
| 清空资源包、导入覆盖、资产覆盖/批量操作 | Modal，明确对象、影响范围和主次按钮                   |
| 字段数量上限、目录名/目标路径错误       | 字段或操作区内联 WarningNotice/错误文本               |
| ZIP 缺文件、非法 JSON、导出问题         | 全局操作 Modal 或已有 ExportValidationDialog 的新外观 |
| ID 范围编辑与签名状态                   | Design Modal；feature 组合范围规则与签名 adapter      |
| 离开页面且有未保存修改                  | 保留浏览器原生 `beforeunload`                         |

确认组件只封装呈现和 pending/disabled/focus 行为；具体删除、覆盖、导入和清空动作仍由对应 feature owner 提供。若锚点式确认已覆盖需求，不建立参考项目的大型 overlay coordinator。

`info/IdRangeEditor.tsx` 不保留 HTML `<dialog>`、`showModal()` 或 `close()`。它迁到 Design Modal 后仍需保持提交/取消语义、Escape、焦点回收、主题、滚动和 reduced-motion；签名逻辑不进入 Modal 组件。

ExportValidationDialog 保留当前业务选择：无 issues 时直接导出；有 error 或 warning 时展示分组问题，用户可返回修改，也可明确确认后继续导出。UI 不能把 error 自动改成不可绕过的阻断。

## 6. Motion、焦点与滚动

- `DesignPreferencesProvider` 在本项目固定提供 `isHighAppearance: true`，不新增用户偏好 store。
- 继续支持 system/light/dark 和跨标签 storage 同步。
- 动效统一经过 `useReducedMotion`/`useMotionProps`；reduced-motion 下关闭非必要位移和缩放。
- Modal、Popover、Dropdown、Select 和移动菜单必须支持键盘打开/关闭、焦点陷阱或正确回收。
- 长 Modal 使用 portal + ResizeObserver + ScrollMask/ScrollShadow，避免内容溢出后关闭按钮不可达。
- 不引入 SmoothScroll、旧 Safari media query fallback 或 inert polyfill。

## 7. 全局样式归属

保留在 `app/globals.scss`：

- Tailwind 层、主题 runtime 样式；
- body/background、共享背景图、文本与选区；
- `--safe-h-dvh`、`--safe-h-dvh-half`；
- 通用滚动条；
- App Shell 使用的 `--navbar-height` 和移动菜单滚动 utility。

迁出或删除：

- `.surface-pressable`：4 个原生按钮改为 Design Button；8 个包裹独立子按钮的展示容器改为非 pressable Card；
- `.bg-checkerboard`：迁到 asset feature 样式；
- 参考公告轮播动画、driver.js、dotted underline、账户/站点偏移变量：无调用者，不迁入。

## 8. UI 验收

- 不比较当前草案 UI 的像素等价。
- 与参考基准比较组件层级、焦点、滚动提示、响应式和操作反馈模式。
- [11-依赖 Patch 迁移矩阵](./11-依赖Patch迁移矩阵.md)选中的 UI Patch 必须原样迁入；UI 验收以应用 Patch 后的参考行为为准。
- 覆盖 12 个 Screen 的空状态、有选择状态、长列表、错误状态和危险操作。
- 至少验证 375、768、1280、1920、2560 像素宽度。
- 键盘覆盖 Tab/Shift+Tab、Enter/Space、方向键、Escape；关闭 overlay 后焦点回到触发器。
- `IdRangeEditor` 覆盖打开、编辑、提交、取消、Escape、长内容滚动与关闭后的焦点回收。
- 扫描业务源码，除 `beforeunload` 外不得残留直接 `alert`/`confirm`。
