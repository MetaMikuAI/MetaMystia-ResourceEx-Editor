# 验证与回归清单

## 1. 验证策略

项目没有 test script 或自动化测试套件。每个实施 Task 使用 TypeScript、focused Prettier、diff check、确定性夹具和对应运行时流程共同验收；静态检查不能替代运行时功能验证。

迁移设计阶段只执行文档格式、文档链接、占位标记和 diff 一致性检查，不建立项目代码或运行时通过结论。

## 2. 确定性夹具

实施前建立四类输入：

1. 最小有效 ResourceEx 包；
2. 包含旧字段/缺省字段的兼容迁移包；
3. 分别不带 `LICENSE.md`、带空 `LICENSE.md`、带非空 `LICENSE.md`，并包含 `assets/**`、被 JSON 引用与未引用的非 `assets/` 文件、嵌套空目录和 `__MACOSX/**` 的完整包。
4. 包含所有 DialogAction，且 Branch 同时具有 `price`/`text`/`jump` 的动作包。

每类记录：

- 输入文件 SHA-256；
- 归一化后 JSON；
- 导出 `ResourceEx.json`；
- ZIP entry 名称、目录标志和排序；
- 每个资产 SHA-256；
- 导入后与导出后的 LICENSE；
- 预期错误/警告。

兼容迁移包必须分别覆盖：

- `packInfo` 存在且遗留顶层包信息也存在：只采用 `packInfo`；
- `packInfo` 整体缺失：由遗留顶层字段构造；
- 集合缺失或为 `null`：归一化为 `[]`；
- 集合为其他非数组值：返回带路径的错误；
- `packInfo.license` 存在但无 `LICENSE.md`：不作为 license fallback；
- 不存在或为空的 `LICENSE.md`：归一化为 `license: ''`，再次导出时不生成该条目；
- 非空 `LICENSE.md`：文本内容原样写回；
- 规范化状态始终包含 `packInfo` 和十个必需数组，序列化也始终输出十个集合。

动作包必须把“当前导出会裁剪 Branch `price`”记录为迁移基线；本次结构迁移不能把它误写成已修复行为。

若现有样例含真实数据，只在项目根 `.tmp/` 中使用且不得提交；任务结束时保留并列入交接，不阻塞任务完成，用户后续另行要求时再清理。

## 3. 静态检查

每个实施切片：

```bash
pnpm exec tsc --noEmit
pnpm exec prettier --check <changed-files>
git diff --check
git diff --cached --check
```

最终额外运行：

```bash
pnpm build
```

记录 baseline warning 与新增 warning，不能混写。

### 非业务参考一致性

每个选中的 Design/theme/shared/browser 文件额外记录：

- 固定参考路径与目标路径；
- 参考实现的最小依赖闭包；
- 除 import、类型 owner 和偏差台账外的内容 diff；
- 每个实质差异对应的 D 编号；
- 未迁入模块没有目标调用者的扫描证据。

不能用“来自参考项目”替代必要性证明，也不能用“业务不同”解释未登记的基础行为漂移。

依赖 Patch 另按 [11-依赖 Patch 迁移矩阵](./11-依赖Patch迁移矩阵.md) 验证：矩阵选中的文件与固定提交内容完全一致，`package.json` 按包名逐项登记，`pnpm install` 无 patch 失败，lockfile 含对应 hash；不得把手改 patch 当作“适配”。

## 4. 运行时矩阵

| 区域       | 必须验证                                                                  |
| ---------- | ------------------------------------------------------------------------- |
| Archive    | 空白创建、有效 ZIP、缺 ResourceEx、非法 JSON、LICENSE、旧字段、entry 分类 |
| Asset      | 上传、覆盖、预览、复制、移动、删除、空目录、引用回写、URL revoke          |
| Unsaved    | 数据/LICENSE/资产原子触发，取消/失败不复位，成功导出复位，离页提醒        |
| Domain     | wire 归一化、Label 保留词/非法字符、ID 范围/重复、签名、引用缺失          |
| Editors    | 12 路由选择、新增、编辑、删除、排序、跨实体引用                           |
| Dialogue   | CG/BG 清空、Sound、Branch 当前裁剪结果、Goto、End、空 actions 省略        |
| Theme/UI   | system/light/dark、高外观、跨标签 storage、reduced motion、键盘与 overlay |
| Responsive | 移动导航、窄屏编辑器、桌面双栏、1920/2560 断点                            |
| Build      | 最新浏览器目标、无兼容 polyfill、静态 export、直接刷新路由                |

### 静态导出与托管

- `next build` 必须生成 `out/index.html`、`out/404.html`、12 个 route HTML、对应 RSC payload、`out/_next/**`、public assets 与 `_next/static/media` 字体。
- 用与生产一致的静态服务器规则启动 `out/`，至少直接请求 `/`、`/info`、其余 11 个编辑 URL、404、一个 `_next` chunk、一个 public asset 和一个字体文件。
- extensionless route 使用 `$uri` → `$uri.html` → `$uri/` fallback；根页客户端 replace 到 `/info`，不能依赖 Next redirect/rewrites。
- 刷新每个 route 后功能可用，客户端跨 route 导航不请求不存在的 Node/API endpoint。
- 扫描 `app/**` 与 `next.config.ts`，不得出现 Server Action、请求态 cookies/headers、动态 Route Handler、rewrites/proxy、默认图片优化或运行时 Node-only 依赖。
- 构建期 `next/font/google` 请求必须按原样 Next Patch 使用 `fonts.loli.net`/`gstatic.loli.net`，不访问原 Google Fonts 域名；浏览器运行时只加载导出产物中的自托管字体。
- 运行时不读取只能由 Node server 提供的环境变量。
- Nginx/静态服务器的缓存、压缩与安全响应头属于部署配置，不通过 Next runtime 实现。

## 5. 浏览器检查细则

- 使用真实浏览器；无可复用会话时使用 Playwright。
- 检查 console 和 network。
- 覆盖键盘打开、选择、关闭和焦点回收。
- 覆盖 reduced motion。
- 覆盖 light/dark/system。
- 覆盖多个同时可见标签页的主题 storage 同步。
- 覆盖 Modal portal、长内容 ScrollMask/ScrollShadow、关闭后的焦点回收。
- 覆盖 `IdRangeEditor` 从原生 `<dialog>` 迁移后的打开、提交、取消、Escape、焦点回收与滚动；业务源码不再调用 `showModal()`/`close()`。
- 覆盖 Select 分组、禁用项、description、长列表打开/键盘滚动和 string/number 值；按参考 patch 验证打开时不会强制滚动到已选项。
- 覆盖导出校验三条路径：无 issues 直接导出；有 issues 返回修改时不导出且 dirty 不变；明确确认“仍然导出”后成功下载并置 clean。
- 覆盖 4 个 Design Button 表面和 8 个含独立子操作的非 pressable Card，确认没有嵌套交互控件或伪造 `role=button`。
- 覆盖 persistent asset preview URL 的替换、删除、重复导入与 Provider 卸载；覆盖四个图片尺寸读取调用者的成功、加载失败和取消路径，瞬时 URL 每条路径均只 revoke 一次。
- 覆盖 375、768、1280、1920、2560 像素宽度。
- 不要求当前草案 UI 像素等价；按参考项目成熟布局、焦点、响应式和反馈模式验收。
- 扫描确认业务源码除 `beforeunload` 外没有直接 `alert`/`confirm`。
- 所有 agent 启动的 Playwright/浏览器会话、开发/静态服务器和后台进程在阶段结束时关闭。
- 可配置的浏览器、Playwright、npm/pnpm 等任务专用缓存指向 `.tmp/cache/<tool>/` 并随阶段清理；不得未经明确授权清理用户级或其他项目共享缓存。
- 临时截图、trace、脚本、日志和生成目录统一写入项目根 `.tmp/`；明确交付物写入文档指定路径。`.tmp/` 普通临时文件在阶段结束时保留并列入交接，不阻塞任务完成，用户后续另行要求时再清理。
