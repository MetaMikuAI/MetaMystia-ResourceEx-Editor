# 非业务能力同步与偏差台账

## 1. 总则

两个项目业务完全不同，不机械复制参考仓库，也不把参考目录当作模板整包搬入。同步单位是“本项目实际需要的同类非业务能力及其最小依赖闭包”。

选中一项能力后：

1. 固定参考提交中的实现、行为和文件边界是默认基线；
2. 先复用参考源码，再适配 import、目标业务契约和运行环境；
3. 不能仅因当前草案更简单或调用者较少而另写弱化实现；
4. 不迁入没有本项目调用者、只服务参考业务或会制造死代码的模块；
5. 每个实质偏差必须在本文件登记参考文件、目标文件、差异和约束原因。

选中前先过必要性门：

- 是否有目标调用者或已确认的用户体验/工程要求；
- 是否承担可观察行为，而不是只为参考目录或实现细节服务；
- 浏览器/框架原生能力或局部常量是否已经足够；
- 新抽象、全局声明和依赖的成本是否与收益相称。

参考一致性只约束通过必要性门的能力，不能反过来成为引入能力的理由。

分类：

| 标记 | 含义                                                                   |
| ---- | ---------------------------------------------------------------------- |
| S    | 同步：能力与依赖闭包适用，保持参考实现和行为                           |
| A    | 适配：保留非业务机制，仅替换本项目业务契约、路径、环境或明确浏览器目标 |
| E    | 排除：只服务参考业务或与目标工程约束冲突                               |
| U    | 未迁入：通用但本项目没有调用者，不为目录对称制造死代码                 |

“U” 不表示自行重写；将来若本项目需要该能力，应重新以固定参考文件为起点。

## 2. memoize 必要性

参考基线 `d3b06126676430943856dfadc0bc8170920f9f72` 中：

- `app/design/theme/colors/utils.ts` 导入 `app/shared/utilities/cache/memoize.ts`；
- `swapColorScale` 由使用 `WeakMap` key 的 `memoize` 包装；
- 本项目当前 `src/design/theme/colors/utils.ts` 也保持同一调用关系。

调用边界：

- `swapColorScale` 只在 `semantic.ts` 模块初始化时使用；
- 输入只有固定的 `colors.black`、`colors.blue`；
- 返回对象立即被展开或读取属性，没有引用身份观察者；
- 缓存不在运行时热路径上提供可验证收益。

目标不迁入 memoize。`swapColorScale` 保持普通纯函数，`semantic.ts` 维持直接调用，不增加 black/blue 反转色阶常量。这里保留参考算法和输出，只删除没有必要的缓存机制；这些小规模计算仅发生在模块初始化，不需要另做性能优化。

## 5. Browser infrastructure

| 参考文件/能力                                   | 分类 | 目标处理                                                             |
| ----------------------------------------------- | ---- | -------------------------------------------------------------------- |
| `storage/contracts.ts`                          | A    | 只保留目标调用者实际需要的 get/set/remove 契约                       |
| `storage/safeStorage.ts`                        | A    | 保留 local/session/memory、无抛错和失败后防陈旧读取；按 D09 缩小协议 |
| safeStorage optional local-cache exports        | E/U  | 只服务未迁入的账户 snapshot/cache                                    |
| `compatibility/mediaQuery.ts`                   | E/A  | 明确只为 Safari < 14；本项目最新浏览器目标下直接使用标准事件 API     |
| `storage/createPersistMiddleware.ts`            | E/U  | 本项目不使用 Zustand 持久化 store                                    |
| `crossTab/**`                                   | E/U  | 本项目不迁入参考 store 同步、IndexedDB lock 和账户状态               |
| `compatibility/checkCompatibility.ts`、platform | E/U  | 旧浏览器/平台业务未使用                                              |
| `dom/setScriptUrlTag.ts`、`waitDomReady.ts`     | U    | 当前目标没有脚本注入或 DOM-ready 调用者                              |
| `browser/crypto/idRangeSignature.ts`            | A    | 本项目专属能力；沿用现有签名协议，不冒充参考实现                     |
| `browser/images/readImageDimensions.ts`         | A    | 本项目四个图片校验调用者共用；统一 transient object URL 生命周期     |

本项目当前三个调用面只读写主题、公告已读版本和资产视图偏好，不使用 `length`、`key`、`clear`、mode、managed-key 枚举或 optional local cache。目标不复制参考账户/跨标签 store 驱动的完整恢复协议，但必须修复当前实现在持久层写入失败后可能重新读回陈旧值的问题。

D09 的目标行为固定为：

- 公开面只有 `getItem`、`setItem`、`removeItem`；
- 初始化按 localStorage → sessionStorage → memory 选择；内部 shadow Map 与 tombstone Set 只跟踪本实例实际访问过的 key，不枚举全局 storage；
- `getItem` 成功得到字符串时写入 shadow 并清除 tombstone；成功得到 `null` 时删除 shadow 并写入 tombstone；
- 首次 `getItem` 抛错且该 key 没有 shadow 时，立即写入 tombstone 并返回 `null`；
- `setItem` 先写 shadow 并清除 tombstone；`removeItem` 先写 tombstone 并删除 shadow，再访问持久层；
- 当前持久层任一 read/write/remove 抛错后，本实例永久降级到下一层；local 降级时用 shadow/tombstone 初始化 session，session 再失败则只用 memory；
- 降级后下层 storage 只作为 shadow 与未来写入的持久化 sink，不作为旧值 source；未访问过且 shadow 未知的 key 返回 `null`，tombstone 优先于任何下层旧值；
- 不实现参考账户场景的恢复重试、managed-key 持久化、fallback mode 持久化或 optional cache；
- hydration 后的主题、公告版本和资产视图偏好使用该 adapter；首屏 theme script 仍以 try/catch 直接读取 localStorage；
- 跨标签主题同步只在 localStorage 可用时成立，运行中降级后不伪造 cross-tab 一致性。

## 10. 实施验证

每个非业务切片：

1. 记录固定参考文件和目标文件；
2. 先同步参考文件及其最小依赖闭包；
3. 将业务接入适配作为独立工作区 diff 呈现，不混写不可解释的重构；
4. 用 no-index/内容 diff 审查所有非 import、类型 owner 和已登记偏差的变化；
5. 新偏差先写入本台账，再实施；
6. 运行目标调用者的 TypeScript、格式、构建和浏览器行为检查。

验收不是“目录看起来相似”，而是：

- 已选能力的核心算法和交互行为可追溯到固定参考文件；
- 所有差异都能归因于本项目业务、明确工程约束或目标调用面；
- 没有从当前草案继续保留一套语义重复的非业务实现；
- 没有为参考目录对称引入无调用者代码。
