# ResourceEx Editor 整站视觉审计

状态：整站视觉收口与生产静态回归已完成
审计日期：2026-08-01
统一视口：桌面 1440 × 1000；移动端 375 × 844

## 1. 审计方法

本轮使用当前工作树启动真实 Next 开发环境，通过正常页面入口访问 12 个路由。每个实体页都通过页面自身的新建、选择或添加操作构造代表性内容，不用只看空状态替代有数据状态；复杂页继续展开嵌套章节并检查 Select、Switch、Tag、Popover、删除、排序和移动导航。

审查同时包含三类证据：

1. 同视口截图的直接视觉检查，重点观察高度、定位、圆角、颜色、间距、图标、文字层级和横向溢出。
2. DOM/CSS 实测，读取控件矩形、圆角、滚动宽度、选中/无效状态和菜单最终高度。
3. 源码 owner 扫描，检查页面私有色值、重复 Surface、局部控件尺寸覆盖、虚拟列表和未统一的操作组件。

临时截图只用于本轮前后对照，最终验证结束后删除；本文件保留可复核的状态、操作和测量结果，不把临时输出目录作为长期交付物。

## 3. 已收口的跨页面规则

### 3.1 骨架与 Surface

- 普通实体页统一使用共享列表面板、列表项、详情面板、详情标题和章节组件。
- 固定视口高度的实体列表和资产目录把标题留在外层，并由共享 `ScrollShadow` 承载内容滚动；移动导航继续由 HeroUI `NavbarMenu` 直接持有 Portal 与滚动，页面主内容不建立多余局部滚动区。
- 通过列表“新建”操作增加实体后，共享列表会展开并在新项目实际渲染后自动滚到末项；减少动态效果开启时使用即时滚动。
- 未选择详情使用统一无方向性文案；移动端不再出现“左侧”或裸 `+` 指引。
- 一级面板、二级章节和列表项使用固定层级，不以页面私有阴影制造深度。
- 对话树和资产目录保留业务所需结构，但颜色、圆角、边框和操作仍复用同一设计系统规则。

### 3.2 高度、定位与圆角

- 默认 Input、Select 及同行操作为 40 px；桌面紧凑操作组整组为 32 px。
- 移动密集行内操作保留 40 × 40 px 点击区；导航和独立主入口使用 44 px 触控高度。
- 表单控件、同行按钮和普通图标按钮的最终圆角均为设计系统 `medium`，浏览器实测为 12 px。
- 卡片、章节、列表项和 Badge 仍按层级分别使用 `large`、`medium`、`small`；统一性指同类同层级一致，不把所有元素机械改成同一圆角。
- 作者、食材、闲聊、后置事件、后置任务、羁绊对话等“输入/Select + 删除”行已按各自行高对齐；纯图标按钮不再因文字宽度改变布局。
- 出没地点、羁绊标题和立绘配置已经过桌面截图复核，长中英标题、说明入口和右侧 Switch 不再互相挤压。

### 3.3 颜色与状态

- 页面通用背景、文字、边框、危险、警告、成功、焦点和选中态均使用 Design 语义 Token。
- 料理、食材和酒水标签使用资源标签语义色；顾客喜好与厌恶标签使用各自对应配色，并保留文字、边框和 `aria-pressed`/`aria-invalid` 状态。
- 真实交互实测：食材“肉”、料理“肉”和酒水“低酒精”点击后背景 alpha 明显提高；顾客同一标签同时进入喜欢/讨厌时会显示冲突并设置 `aria-invalid=true`。
- 深色主题料理真实内容页已检查：列表选中、预览/删除图标、字段 Surface、标签默认/选中和上传空态均可辨；console 无 warning/error。
- 状态 Badge 使用 `danger-foreground`、`warning-foreground`、`success-foreground`，不再硬编码白字。

### 3.4 图标、弹层与下拉

- 新增、删除、复制、预览、刷新和折叠均使用正式图标组件；不再用裸字符、Emoji 或页面内临时 SVG 代替。
- 料理、食材、酒水和食谱预览使用与删除按钮同组的纯图标按钮，在 Popover 中显示，不再使用 Modal。
- Select 使用普通滚动列表并关闭虚拟化。165 项和自定义料理分组的真实下拉已复核，没有机械迁移造成的大块空白。
- 说明入口使用统一 InfoTip 图标、语义前景色和 Tooltip，不再用低对比度“说明”文字挤占字段标题。

### 3.5 移动导航

- 展开菜单是一个连续 Surface，当前路由使用 primary 浅色选中态，不再把入口做成多张阴影卡片。
- 375 × 844 视口中，导航高 64 px，菜单动画稳定后的 top 为 64 px、bottom 为 844 px、高度为 780 px；菜单可滚动，主体滚动被锁定。
- Escape 关闭后焦点回到菜单按钮并恢复主体滚动；菜单项和开关入口保持 44 px 高度。

## 4. 源码一致性扫描

- `qq-blue`、`rednote` 和其他机械迁移遗留品牌色定义已删除，当前无调用者。
- 编辑器业务页未发现可由语义 Token 表达的十六进制、RGB 或 Tailwind 固定色；仅资产透明棋盘格保留固定白/灰，这是内容语义而非主题色，并已登记为设计规范例外。
- Input、Textarea、Button 与共享 Select 的默认圆角由 Design/共享 owner 固定；页面只在需要与同行控件等高时覆盖高度，不覆盖颜色或另一套圆角。
- `tsc --noUnusedLocals --noUnusedParameters` 扫描未发现未使用的迁移代码或定义。
- 项目没有自动化测试套件；本轮证据来自确定性扫描和真实浏览器操作，不称为测试套件通过。

## 5. 本轮发现并修正的细节根因

1. 业务页曾分别覆盖 Button、Input 与 Select 高度，导致看似同一行的控件实际为 32/36/40/44 px。修正后只保留“默认表单 40”“桌面紧凑组 32”“移动触控 40/44”三类明确规则。
2. 页面直接使用不同圆角 class，导致作者删除、料理食材删除和对话操作视觉接近但不完全一致。最终圆角由共享 Button/Input/Select owner 固定为 12 px，同层级页面不再另造值。
3. 标签曾只改数据没有可见状态，且不同业务共用无语义的默认按钮色。现在标签色由资源标签 token 映射，选中态同时改变背景、边框和可访问状态。
4. 帮助文字、空态和禁用文案曾通过低 opacity 处理，造成浅色背景难辨。现在使用前景语义色阶；状态 Badge 使用对应 foreground token。
5. HeroUI Select 的尺寸 class 曾加在错误 slot 或与 `size=sm` 冲突，产生同行按钮 40 px、Select 32 px。当前由共享 trigger slot控制，并在资产批量栏实测全部 32 px、12 px 圆角。
